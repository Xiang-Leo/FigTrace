# 浏览器界面与批量导入设计

状态：浏览器方案已确认，核心流程已进入 0.1 实现；实际功能与限制见 [运行说明](running.md)。早期对话中的交互示意使用虚构素材，不读取或传输真实文件，实际应用的上传入口会向所连接的后端传输文件。

## 图库工作台

采用图片优先的三栏布局。左侧按项目、待整理状态和素材来源导航，中间展示缩略图，右侧展示选中 Figure 的版本、源文件、路径和标签。窄屏下导航折叠，详情转为独立面板或移至图库下方。

顶部保留全局搜索与“添加素材”，明确当前连接本机服务还是远程服务。搜索首版覆盖文件名、项目、路径、标签与备注；AI 语义搜索后续接入。

默认将同一 Figure 的多个版本折叠成一张卡片，以当前采用版本作封面，显示版本数；用户可切换到文件版本视图。图片卡片保留名称、格式、版本数和必要的异常状态，详细路径、生成参数等信息按需展示。

单击选图更新详情，进入大图视图后可切换版本或并排比较。多选时显示批量添加标签、归入项目和版本归组操作栏；每张图不重复摆放所有操作。AI 建议与已确认标签区分显示。

预览失败、原文件离线和未关联源文件是可处理状态。卡片继续可见，并在详情提供重试、重新定位、手动指定封面或关联文件入口。

## “添加素材”的两个入口

### 批量上传：向后端保存副本

用于收纳新素材，或将访问者电脑上的文件传到云端后端。支持多选文件、选择整个文件夹，以及在支持的浏览器中拖拽文件或文件夹；不支持文件夹选择或拖拽时保留多文件选择入口。

流程：选择文件 → 核对清单 → 设置项目、标签与保存方式 → 传输 → 入库 → 后台生成预览。

清单展示文件数量、总大小、相对目录、支持情况和目标位置。选择文件夹时默认保留相对目录层级，不将目录名自动当作 Figure 版本关系；可选择按子目录辅助整理。导入前不要求逐张填写信息，也不强制使用 AI。

同名不同内容保留为不同素材，不覆盖已有文件。重复内容在确认后可复用存储，但保留此次导入的来源关系。客户端基于名称和大小只能给出初步提示，不能在没有可靠内容指纹时声称发现完全重复的文件。

上传来源和后端保存位置分开记录。浏览器不会提供可用于后端持续扫描的用户电脑绝对路径；后续编辑原文件也不会自动更新已上传副本。文件夹上传通过相对路径保留目录关系，不代表自动同步。

### 关联已有目录：让后端直接索引

用于后端已经能够访问的素材，包括本机目录、已同步到本地的网盘目录和挂载目录。界面选择的是后端允许访问的目录，通过后端目录浏览器或手动填写路径完成。

不复制原文件，后端后台扫描并定期检查变化。关闭浏览器不会中断后端扫描。云端模式只显示服务器目录，不能将浏览器所选电脑目录当作服务器路径。

对已有的上千张本机图片，优先使用关联目录；大批量云端迁移也可先通过现有同步工具将素材送到服务器，再关联目录。

## 浏览器实现边界

- 多选文件使用 `<input type="file" multiple>`；文件夹选择使用独立的 `webkitdirectory` 输入，读取 `File.webkitRelativePath` 保留相对路径。现代浏览器已普遍支持文件夹选择，但仍需运行时检测和旧版本回退。[MDN 文件输入](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)、[MDN 文件夹选择](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)
- `showDirectoryPicker()` 仅作为可选增强，不作为全平台必需条件，因为它仍有浏览器支持及安全上下文限制。[MDN 目录选择 API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)
- 文件扩展名和浏览器提供的 MIME 仅作提示，后端校验类型和内容；把不具备预览能力的源文件保留为关联素材，不执行其内容。
- 后端自行生成存储标识，校验用户提供的相对路径，不允许目录穿越；不同批次及同名文件需避免互相覆盖。

## 上传队列与恢复

为每一批导入保存批次标识，每个文件有独立任务状态。清单分页或虚拟滚动；文件按需读取和分片发送，不一次性将几千张原图读入浏览器内存。初始并发拟设为 3 个文件，根据大文件、网络条件和服务端容量调整。

使用支持可恢复上传的协议，例如 tus，保存服务端确认的传输偏移量；客户端和后端都需要实现相应支持，不是浏览器文件选择控件自动提供的能力。[tus 协议](https://tus.io/protocols/resumable-upload)

任务提供暂停、继续、失败重试和取消。取消上传仅清理对应的临时上传数据，不删除用户原文件；已成功入库的文件不因同批其它文件失败而回滚。临时数据保留期限、单文件大小和容量上限由后端配置，并在超限时给出具体原因。

关闭或刷新网页后，不承诺仍在继续传输浏览器文件。后端保留未过期的上传进度，重新打开后可能需要用户重新选择原文件；客户端确认匹配，服务端校验后才续传。后端已接收完成的素材，其预览生成等任务继续运行。

任务状态至少区分：待上传、上传中、暂停、待校验、已入库、预览处理中、就绪、失败与已取消。文件传输完成不等于预览已生成；解析失败不应显示成网络上传失败。提供只重试失败项的操作。

AI 分析在上传入库后单独排队，默认关闭；用户启用时展示分析服务和发送范围。重复提交同一上传完成请求不得重复创建素材记录。

## 首版验收场景

1. 批量选择多个文件，统一设置项目和标签后入库。
2. 上传包含多层子目录的文件夹，正确保留来源层级，允许跨目录同名文件共存。
3. 上传中断后恢复；刷新网页后重选原文件可以恢复未过期任务，并正确拒绝错误文件。
4. 同批包含损坏文件、重复内容和不支持预览的源文件，其它文件仍正常完成。
5. 清楚区分传输进度、入库结果和预览进度，并能仅重试失败项。
6. 本机与云端模式准确展示目标位置；本机目录索引不额外复制原文件。
7. Windows、macOS、Linux 的目标浏览器组合验证多选、文件夹导入及降级行为；用 5,000 文件清单检查界面响应和内存占用。
