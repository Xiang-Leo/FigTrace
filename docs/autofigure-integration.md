# AutoFigure 科研图编辑

FigTrace 已实现可选的 AutoFigure-Edit 接口适配、SVG 预览与浏览器基础编辑。转换流程是：**图库选图 → 主动发送至 AutoFigure → 重建 SVG → 保存为同一 Figure 的新版本 → 编辑并另存版本**。未启用服务时，图库与已有 AI 分类、生成正常工作；已有 SVG 的基础编辑也不需要推理服务。

适配依据为 [ResearAI/AutoFigure-Edit](https://github.com/ResearAI/AutoFigure-Edit/tree/16f3749e9d512bdf7b7b55c162307bc289750b7a)，固定源码版本 `16f3749e9d512bdf7b7b55c162307bc289750b7a`。本次接入没有安装或捆绑其机器学习运行时，也未验证真实模型的重建质量和耗时。

## 运行独立服务

AutoFigure 应使用独立 Python 环境或其上游容器。不要把上游依赖安装到 FigTrace 的 `.venv`：上游依赖 PyTorch、Transformers 等，且要求 `Pillow>=10,<12`，与 FigTrace 的锁定版本不同。安装说明以该固定版本的 [README](https://github.com/ResearAI/AutoFigure-Edit/blob/16f3749e9d512bdf7b7b55c162307bc289750b7a/README.md) 和 [requirements.txt](https://github.com/ResearAI/AutoFigure-Edit/blob/16f3749e9d512bdf7b7b55c162307bc289750b7a/requirements.txt) 为准。

1. 单独克隆上游仓库并检出上述提交，准备独立环境，安装其依赖。
2. 配置所选分割后端，准备背景移除模型及其访问权限。使用本地 SAM 时还需单独安装 SAM；选择远程分割不会移除本地 RMBG/PyTorch 依赖。
3. 在上游仓库目录、正确的已激活环境中启动固定端口服务：

```sh
python -m uvicorn server:app --host 127.0.0.1 --port 8788
```

这个地址由 FigTrace 后端访问。若两个服务位于不同机器或容器，`127.0.0.1` 不能代表另一台机器或另一个容器。远程连接须使用 HTTPS 和受控的认证代理；上游原始服务没有 FigTrace 的登录保护。设置中的服务访问令牌会作为 Bearer token 发给该代理，并不会替上游自动启用认证。

本地 SAM 的 GPU 环境应遵循 [SAM 3 官方安装说明](https://github.com/facebookresearch/sam3)，包括 Python、PyTorch、CUDA 与权重访问要求。浏览器可跨平台使用；这不表示已验证 macOS、Windows 或 CPU 上的推理速度。

## 在 FigTrace 中配置

打开「图库设置」中的「科研图编辑 · AutoFigure」，填写以下内容：

| 设置 | 用途 |
| --- | --- |
| 启用服务、服务地址 | 默认为关闭；本机地址可设为 `http://127.0.0.1:8788` |
| 服务提供商 | `custom`（OpenAI 兼容）、`openai_response`、`openrouter`、`bianxie` 或 `gemini` |
| SVG 重建模型 | 填写所选接口实际提供、支持图片输入的模型名称；启用后必须填写 |
| 模型接口地址、模型 API 密钥 | 默认地址为 `https://api.openai.com/v1`；切换提供商时必须同时填写该提供商适用的地址和密钥，地址不会自动切换 |
| 图像分割服务 | `local`、`fal` 或 `roboflow`；远程分割须填写对应 API 密钥 |
| 服务访问令牌 | 可选，用于访问 AutoFigure 前的认证代理，与模型 API 密钥不同 |

模型及分割密钥保存在 FigTrace 后端。用户发起转换时，FigTrace 将图片、模型接口地址和这些密钥发送给配置的 AutoFigure 服务，由该服务调用模型；因此必须使用可信的 AutoFigure 服务。没有通过环境变量替代模型密钥的隐式配置。远程 SAM 还会收到输入图片，模型调用可能产生费用。

界面只返回密钥是否已保存，不回显其内容。留空保留同一目标的原密钥；更换服务地址、模型提供商/接口或分割后端时，对应旧密钥不会自动转发到新目标，需要重新填写。运行中的任务完成前不能更改服务设置。

「保存并测试连接」只检查上游 `/healthz`，不运行模型，也不验证模型名称、密钥、GPU 或权重是否可用。真实推理需用获准发送的样例图另行验收。

## 转换、编辑与版本

在图片详情选择「转为可编辑示意图」，确认接收服务后点击「发送图片并转换」。输入支持 JPG/JPEG、PNG、WebP、BMP 和 GIF，最大 20 MiB、4000 万像素；PDF/TIFF 等请先导出所需页面。目录扫描不会自动发起转换。

后台上传图片并提交上游任务，随后通过 `/api/history/{job_id}` 查询完整产物。任务记录保存在图库内，浏览器关闭不影响后台工作；重新打开该图片的转换面板即可继续查看。界面不会把部分产物当成成功，也不提供上游细分步骤的实时日志。一小时内未发现完整 SVG 时任务标记失败，可到上游检查日志；已有远端编号时，「检查原任务进度」只查询和取回结果，不重新提交推理。连接超时或 FigTrace 重启后的不确定提交不会自动重发，没有远端编号时需核对上游记录。

完整 SVG 通过校验后写入 FigTrace 管理的 `originals`。它保留原 Figure 的项目、标签及版本关系，记录父版本、服务、模型、远端任务编号和输入指纹。转换和编辑保存都会把 **Figure 状态改为草稿**，但不会改变「当前采用版」；复核后可在版本列表手动采用新版本。重复确认同一请求不会重复生成版本。

打开 SVG 后点击「编辑 SVG」，可选择文字或图形，修改文字、填充色、描边色、字号及水平/垂直位移。文字分段和既有变换会保留。预览使用独立的 SVG 图片资源，不把 SVG 元素插入应用页面；保存时后端再次校验，并另存新版本。详情中的「查看来源版本」可回溯父版本。

这是 FigTrace 自带的基础元素编辑器，尚未嵌入上游完整的 svg-edit。它不支持任意路径绘制、图层重排、位图像素编辑或完整设计软件功能。可下载当前编辑中的 SVG；「预览 PNG」导出已保存版本、最长边不超过 1600 像素的查阅图，未保存修改时该按钮不可用。

## 格式、授权与备份边界

- SVG 采用白名单校验，最大 12 MiB。支持常见形状、路径、文字、部分样式、渐变、裁剪、局部引用与嵌入的 PNG/JPEG。脚本、外部资源、外部字体、`foreignObject`、动画、滤镜及不支持的 CSS/结构会被拒绝；不能承诺所有合法 SVG 都可预览或编辑。拒绝不会覆盖原图。
- 支持直接设置在路径或线条上的起点/终点箭头；不支持 `marker-mid`、分组继承或样式表定义的箭头规则。箭头内容限 64 个元素且不能引用位图，避免重复绘制导致资源耗尽。
- 重建适合流程图、机制图和架构示意图。部分图标仍是嵌入位图，不能恢复 AI/PSD 原始图层或实验数据。文字、箭头与科学含义需人工复核；文本生成科研图和参考图风格生成尚未接入此流程。
- 上游代码采用 [MIT 许可证](https://github.com/ResearAI/AutoFigure-Edit/blob/16f3749e9d512bdf7b7b55c162307bc289750b7a/LICENSE)，分发时需保留声明。SAM 与 RMBG 权重有各自的访问和许可条件；代码许可不代表模型许可。[RMBG-2.0 模型卡](https://huggingface.co/briaai/RMBG-2.0)规定免费权重用于非商业用途，商业自托管需另行协议。更换背景移除模型尚需额外开发与验证。
- 图库信息备份包含任务、版本与来源关系，不包含原图、生成/编辑后的 SVG、PNG 缓存或服务令牌及模型密钥。请另行备份 `originals` 和关联素材目录；迁移到新环境后重新配置凭据。

接口适配、失败恢复、幂等保存、SVG 校验与渲染可通过仓库测试验证；接口模拟和健康检查不代表真实 SAM/RMBG/LLM 推理已经通过。效果验收应记录实际部署环境、模型、样例、耗时和人工复核结果。
