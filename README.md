# FigTrace

本地优先的图片与科研 Figure 管理工具，帮助用户跨文件夹查找图片，并关联源文件和不同版本。

> 产品方向与浏览器方案已确认，目前已有可运行的 0.3 版本（包含项目工作区、文件移动追踪、Figure 状态与 AI 分类、生成）。下文保留完整产品规划；当前已实现功能、已知限制与启动方式见 [运行说明](docs/running.md)。

## 快速开始

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install -e . --no-deps
npm --prefix frontend ci
npm --prefix frontend run build
.venv/bin/figtrace
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。Windows 命令、数据目录、开发方式和 Docker 部署见 [运行说明](docs/running.md)。

已确认的产品约束：支持 Windows、macOS、Linux，采用网页前端与独立后端；支持定期自动备份；覆盖 JPG、PNG、TIFF、PDF、AI、EPS、PSD 等常用素材；面向上千张图片的个人图库；原文件可位于本地或网盘目录，运行中的数据库保存在后端所在机器的本地磁盘。

## 为什么做 FigTrace

工作和科研中会产生大量图表、插图与设计稿，同一张图常有多个版本，散落在不同项目和文件夹里。仅凭文件名，很难快速回答：

- 我之前做过的那张图在哪里？
- 这张导出图片对应哪个可编辑源文件或绘图脚本？
- 哪个版本用于汇报，哪个用于论文，哪个是最终采用的版本？
- 收藏的参考图能不能和自己制作的图一起搜索？

FigTrace 希望让用户看到图片时，也能找到它的上下文，并将 AI 辅助整理与生成纳入同一套工作流程。

## 核心使用流程

1. 添加项目文件夹，建立跨目录图片索引；原文件保持原位。
2. 在统一图库中浏览缩略图，按项目、标签、文件名和备注查找。
3. 打开图片详情，查看原路径，并关联源文件、绘图脚本或相关数据文件。
4. 将同一 Figure 的不同文件归入一个版本组，标注用途并指定当前采用版本。
5. 按需使用 AI 建议标签、生成描述、识别图中文字，再由用户修正或确认。
6. 后续接入 AI 生成图片，保存结果及生成记录，纳入同一图库管理。

## 管理对象

| 对象 | 表示什么 | 示例 |
| --- | --- | --- |
| Figure | 一个逻辑上的图或作品，可包含多个版本 | 某论文的 Figure 2 |
| 图片版本 | 具体素材文件，带用途、版本说明和预览状态 | 投稿版 PNG、汇报版 JPG、暂不可预览的 AI 文件 |
| 关联文件 | 与某个版本或整个 Figure 相关的源文件、脚本和数据 | SVG、PPTX、AI、Python 脚本、CSV |
| 项目 | 用户定义的工作上下文，可关联多个目录 | 论文 A、季度汇报、个人素材库 |
| 收藏记录 | 参考图及来源信息 | 原文链接、作者、个人备注 |
| 生成记录 | AI 输出的来源和过程 | 提示词、模型、参数、参考图 |

一张尚未整理的图片也能独立进入图库。归组、添加标签和关联源文件都可以稍后完成，避免导入时要求用户填写大量信息。

同一源文件可关联多个导出版本。仅记录源文件路径不能保证复现旧版本；若需要可靠回溯，后续应提供显式保存源文件快照或关联 Git 提交的能力。

## 第一版：让自己的图找得到、对得上

首版面向频繁绘图的个人用户，以本地目录中的已有图片为主。

- **跨目录图库**：添加多个目录，按下方格式支持范围递归扫描、生成缩略图，支持增量重扫；无法预览的素材仍可入库整理。
- **搜索与整理**：按文件名、路径、项目、手动标签和备注搜索与筛选。
- **图片详情**：预览、可读取的尺寸、文件类型、原路径，支持下载和复制路径；本机后端模式提供打开原文件或所在目录的入口。
- **源文件关联**：手动关联源文件、脚本或数据；本机后端模式可调用对应系统应用打开。远程访问提供下载和路径信息，不将服务器路径当作访问者电脑上的路径。
- **版本管理**：手动将图片归为同一 Figure，填写版本说明、用途，并指定采用版本，支持并排查看。
- **基本可靠性**：识别完全相同的文件，提示原文件失联，支持重新定位；重复文件仍保留各自路径信息。
- **自动备份与恢复**：配置定期备份、备份目录和保留数量，显示运行结果，支持从备份恢复整理信息及重新绑定原图目录。

首版验收场景：添加两个项目目录后，用户能够跨目录找到目标图片，将两张图片归为同一 Figure 的不同版本，关联可编辑源文件，并在重启应用后保留这些信息。

第一版暂不展开多人协作、FigTrace 自建的跨设备同步、论文排版、复杂图片编辑和大规模模型集成。已有网盘客户端的同步目录或系统挂载目录可以作为素材来源；直接连接各家网盘 API 留作后续扩展。

## 跨平台与部署方式

采用浏览器界面、后端 API 和后台任务的结构。网页负责浏览与整理；后端负责目录访问、索引、预览转换和备份；耗时扫描与转换在后台执行，并向界面报告进度。

| 运行方式 | 服务和数据库的位置 | 可扫描的原文件 | 访问方式 |
| --- | --- | --- | --- |
| 本机运行 | Windows、macOS 或 Linux 电脑的本地磁盘 | 本机目录、网盘同步目录、系统挂载目录 | 浏览器访问本机服务 |
| 自托管服务 | 服务器本地持久化磁盘 | 服务器目录及其可访问的挂载目录 | 电脑或移动设备通过浏览器访问 |

“全平台”首先指三大桌面系统上的后端运行与浏览器使用，移动设备可作为访问端，不要求在手机上常驻扫描服务。拟提供本机启动方式与容器部署方式，并使用同一套 API 和数据结构。

云端服务不会因为用户打开网页就获得其电脑目录的持续访问能力。首版云端部署需要将素材同步或挂载到服务器，或通过显式上传导入；连接电脑本地目录的常驻连接程序属于后续扩展。浏览器中的目录浏览器展示的是后端允许访问的目录。

本机服务默认仅监听回环地址。本机打开文件的能力只允许本机模式使用；远程部署需提供登录、传输加密及受控的素材目录访问，关闭服务器桌面应用启动能力。扫描与下载接口通过已登记的素材记录访问文件。

## 文件格式支持范围

“支持”分为入库整理、生成预览和编辑原文件三个层级。FigTrace 管理素材与关联关系，原文件编辑仍交给对应工具；不以支持扩展名来承诺所有格式变体都能准确渲染。

| 格式 | 第一版目标 | 预览边界与降级方式 |
| --- | --- | --- |
| JPG / JPEG、PNG | 入库、缩略图和大图预览 | 读取方向与颜色信息，原文件不变 |
| TIFF / TIF | 入库、后台生成浏览器可用的预览 | 多页文件默认首页作封面，按需切页；记录位深，科学数据原值不因预览转换而改变 |
| PDF | 入库、首页封面和按需分页预览 | 保留页码；加密或解析失败时说明原因，仍可管理原文件 |
| AI（Illustrator） | 入库、关联与条件预览 | 优先渲染文件内的 PDF 兼容内容；没有可用兼容内容时显示占位卡，可手动关联导出图作为封面 |
| EPS | 入库、通过转换器生成预览 | 需要可用的 PostScript 渲染依赖；缺少依赖或转换失败时保留文件记录 |
| PSD | 入库、优先提取内嵌合成预览 | 无可用预览时尝试兼容的合成方式；复杂效果可能存在差异，提供手动关联封面的入口 |
| WebP、BMP、GIF、SVG 等 | 通过统一格式处理接口逐步扩展 | GIF 首期以静态封面管理；SVG 生成受控预览，不直接注入页面 |
| 其它源文件 | 允许手动关联，保存类型与路径 | 没有解析器也可作为关联文件保留，不阻塞已有图片的管理 |

多页 PDF/TIFF 首版以整个文件作为素材记录，页面作为子资源，不自动拆成多个 Figure。关联时可以指定页码，后续可扩展将指定页面独立归组。高位深、多通道 TIFF 的预览仅用于查找，需显示所用页面或通道及显示映射信息；不宣称提供科研定量分析功能。

预览状态包含待处理、处理中、可用、缺少依赖、格式暂不支持和失败。格式处理器可独立扩展；单个大文件或损坏文件的转换失败不应中断扫描。转换任务需限制时间、内存和并发，预览缓存可重建，不覆盖原文件。

这些支持边界参考了 [Pillow 格式文档](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)、[Adobe Illustrator 保存说明](https://helpx.adobe.com/au/illustrator/using/saving-artwork.html)和 [psd-tools 合成接口](https://psd-tools.readthedocs.io/en/latest/reference/psd_tools.html)。具体转换器选型及跨平台打包需在实现阶段用样本文件验证。

## 素材位置与图库规模

将原文件、数据库和预览缓存分开存储。建议首版使用 SQLite 保存索引、项目、标签、版本关联和任务记录；缩略图保存在可重建的缓存目录，原文件留在用户指定的位置。

数据库必须位于后端机器的本地磁盘；容器部署使用宿主机本地持久化卷，不放在临时容器层。运行中的数据库不置于网盘同步目录或网络共享文件系统，也不通过网盘让多个后端共同写入。该设计依据 [SQLite 对网络文件系统的说明](https://www.sqlite.org/useovernet.html)。多人并发或多实例服务另行评估数据库方案。

网盘接入首版支持后端可访问的同步目录与挂载目录，具体可用性取决于网盘客户端和系统。仅在线占位文件可能在读取时触发下载：默认不批量拉取此类文件，在可识别时标记为待下载；无法可靠识别占位状态的来源，要求用户选择已下载目录或显式允许读取。未下载、离线、访问失败与文件已删除需区分，断网不自动清除素材记录。

路径采用“素材根目录标识 + 相对路径”，便于迁移后重新绑定根目录。文件路径不作为 Figure 的唯一身份；文件内容指纹用于确认完全相同的内容，按需在后台计算，避免扫描网盘时为了去重强制下载全部文件。

以 5,000 个素材文件作为第一版基准验收规模，并用 10,000 个文件检查增长趋势；这是待验证目标，不是已有性能结果。界面分页或虚拟滚动，缩略图按需加载，扫描分批写入，使用增量检查避免反复转换未变文件。性能评估须记录设备、素材大小与格式组成，并将本地缓存查询耗时与网盘读取、首次解析耗时分开统计。

## 定期自动备份

备份属于 FigTrace 后端功能，即使浏览器关闭也应按计划运行。拟默认每天执行一次、保留最近 7 份成功备份，周期、运行时间和保留数量均可调整。后端停止或电脑休眠期间不能执行，恢复运行后补做一次错过的备份，并记录上次成功时间和下次计划时间。

提供两种明确的备份范围：

- **图库信息备份（首版）**：数据库一致性快照、项目与标签、版本和来源关联、素材目录映射、非敏感配置、手动上传且无法重建的封面，以及备份格式版本与校验清单。明确标注不包含原图片和关联源文件；可再生成的缩略图默认省略。
- **包含原文件的归档备份（后续）**：按用户选择额外包含图片、生成结果与关联源文件，记录遗漏或离线文件，并预估空间需求。应记录每个文件的校验值；跨文件的一致历史快照需要额外快照机制，不能仅靠顺序复制保证。

首版采用 SQLite 一致性备份接口生成数据库快照，参照 [SQLite Online Backup API](https://www.sqlite.org/backup.html)，不直接复制正在写入的数据库文件。备份流程先在本地暂存区生成并验证完整备份包，再交付到用户指定的本地、外接盘或网盘目录；通过临时文件与完成标记区分传输中的包。写入网盘同步目录只表示本地备份已生成，除非能获取同步状态，否则不宣称已上传云端。

新备份完成并通过校验后才按规则清理本应用生成的过期备份，失败时保留已有成功备份。目标目录不可用或空间不足时记录失败并在界面提示，不把未完成文件算作成功备份。密钥与访问令牌不进入普通配置备份，恢复后重新配置；备份目录和应用缓存需从素材扫描中排除。

恢复流程包含选择完整备份、验证清单与版本兼容性、暂停写入、备份当前库、恢复图库信息、重新绑定素材目录和重建缓存。验收需实际恢复到一个空的数据目录，确认项目、标签、版本关联及文件定位均可用；仅生成压缩包不算备份功能验收通过。

## AI 辅助整理

基础图库可在不启用 AI 的情况下工作。AI 是可选的整理助手，采用可替换的模型接口，允许后续连接本地模型或用户配置的云端服务。

优先考虑的能力：

- 建议图片类型、主题和标签，例如折线图、显微图、流程图、示意图。
- 提取可见文字，生成简短描述，为关键词搜索补充信息。
- 后续增加自然语言找图，以及相似图片和可能版本的候选提示。

AI 结果需记录模型和处理时间，并与用户确认的信息区分保存。重新分析不得覆盖用户手动修改的标签和描述。相似度只用于建议，由用户确认版本关系；文件修改时间不能直接等同于版本顺序。

对于科研图片，AI 描述应限于可见内容；实验条件、统计结论和科学含义需要用户或关联材料提供。

## AI 生成图片

在图库与版本管理稳定后加入生成入口。生成结果先进入待整理区，用户选择保存为新 Figure，或加入已有 Figure 的版本组。

保存提示词、模型标识、可获得的生成参数、生成时间与参考图关联。区分生成插图、真实实验图像和参考素材，方便追溯来源。科研用途主要考虑概念示意和配图，生成内容不应被当作实验结果。

## 本地优先原则

- 图片默认留在原目录，本地保存索引、缩略图和整理信息。
- 导入外部参考图和生成结果时，使用用户指定的素材目录。
- 添加目录只建立索引；应用内整理不隐式移动、重命名或删除原文件。
- 默认不向云端发送图片。启用云端分析时，清楚展示服务商和发送范围，允许按目录排除敏感资料。
- 支持定期自动备份和恢复；备份说明需明确区分图库信息与原始图片文件，完整备份包可放入网盘同步目录。

## 界面草案

详细交互与批量上传方案见 [浏览器界面与批量导入设计](docs/browser-interface.md)。

- 左侧：全部图片、项目、标签、待整理、失联文件。
- 中间：搜索栏、筛选条件与缩略图网格。
- 右侧详情：大图、版本、关联文件、标签、备注和来源信息。
- 版本查看：并排预览，并显示用途、版本说明和当前采用标记。
- 设置与任务：素材目录、预览任务进度、转换器状态、备份计划、历史结果和恢复入口。
- 添加素材：批量上传到后端素材目录，或关联后端可访问的已有目录；分别明确保存副本和原位索引的含义。

## 建议实施顺序

1. 建立网页前端与后端 API，跑通本地扫描、JPG/PNG 预览、搜索、详情和索引持久化。
2. 加入格式处理接口，覆盖 TIFF/PDF 分页预览及 AI/EPS/PSD 条件预览和失败降级。
3. 加入项目整理、源文件关联、手动版本归组、网盘来源状态和失联恢复。
4. 实现定期备份与恢复，完成三大桌面系统、服务器部署和 5,000 文件图库的首版验收。
5. 接入一种可选的图片分析方式，验证标签与文字识别是否实际改善查找。
6. 按实际素材检索效果增加语义搜索、相似图片建议。
7. 接入 AI 生成，将输出和生成记录纳入已有的文件与版本管理流程。

已采用 React + TypeScript 网页前端、Python/FastAPI 后端和 SQLite 本地索引实现第一版。完整产品规划中的其它后续能力不代表已经实现；实际完成范围与验证结果以 [运行说明](docs/running.md) 为准。
